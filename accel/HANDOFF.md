# HANDOFF: Intel Arc 130T (8086:7D51) graphics acceleration on macOS

Context for the next agent session, which runs **on the macOS side** of this laptop. Read this whole file before
doing anything. It was written on 2026-11-22 from the Arch Linux side of the same machine, right after macOS was
first installed.

> **Current status (2026-11-22, evening): Gates 0–4 are done.** WindowServer composites on the Arc 130T with zero-copy
> flip and starts automatically at every boot (`scripts/autostart.sh`, `amfi=0x80` in the live config). The user
> confirms that transparency and blur effects, video wallpapers and smooth compositing all work. Open items:
> tearing while windows move, apps outside the allow-list drawing on the CPU, software-only video decode, audio
> (SN6140), the Safari video freeze, brightness and sleep. See `LOG.md` for the details and the latest step.

## 1. Goal and realistic target

The goal is GPU acceleration for the Arrow Lake-H iGPU (Arc 130T, `8086:7D51`, rev 3, Xe-LPG+). Linux i915 reports
graphics 12.74 (stepping B0), media 13 (C0), platform `METEORLAKE`, has_gmd_id. Apple has no driver for it, and WhateverGreen and WhateverXe don't cover it. The only route
is **WTLIntelGfx / XeGfx**: Linux i915 running inside XNU through FreeBSD LinuxKPI, Mesa ANV for Vulkan, and a
Metal-on-Vulkan plugin forked from NullMoth.

What others have reached:

| Machine | GPU | macOS | Result |
|---|---|---|---|
| Lenovo Legion 5 15IAX10 (275HX), upstream dev | 7D67 | Tahoe 26.7 | stages 1-7, WindowServer on GPU for hours, 1 open panic (I-116) |
| ThinkBook 14+ 2024 (155H), samwu07 | 7D55 | **Sequoia 15.8.1** | GPU-composited desktop, zero-copy flip, ~58-60 fps drag, brightness |
| HONOR MagicBook Art 14 (**255H**), change-48 | **7D51** (same as ours) | Tahoe 26.5.2 | GPU-composited desktop, flip, ~40 fps, 1 WS restart per boot |

A realistic "done" here: WindowServer composites on the Intel GPU (Metal → NVMTL → ANV → XeGfx), frames flip to
the panel, and an autostart LaunchDaemon brings it up after login. Most third-party apps will **still draw on the
CPU**. The plugin only gives the Metal device to processes listed in `/Library/GPUBundles/nvmtl-allow.txt`, and
change-48 saw apps hit `vkEnumeratePhysicalDevices -> 0`. Native 120 Hz or panel mode-setting is **not** expected:
XeGfx doesn't mode-set, so the panel stays at the firmware's 1920×1200@60.

## 3. Facts from Linux that matter here (`hardware/`)

- i915 on Linux 7.3 drives this GPU with **`mtl_guc_70.bin` 70.53.0**, **`mtl_dmc.bin` 2.23** and
  `mtl_huc_gsc.bin` 8.5.4. The GuC version is exactly the one linked into XeGfx 0.0.48. There are two GTs: GT0
  render, GT1 media.
- Panel: eDP-1 on **pipe A**, DDI A / PHY A, `1920x1200 @ 60`, pixel clock 154.26 MHz, port clock 540000, **2 lanes**,
  PSR status in `i915_edp_psr_status.txt`. The EDID says `ATNA40CT03-0` (Samsung SDC OLED) and has only one timing
  at 60 Hz. **It is not the 2.8K 120 Hz panel** that some listings mention. The sink supports PSR (0x03), but Linux
  runs it with PSR disabled.
- Pitch: 1920 × 4 = 7680 = 256 × 30. That is already 256-aligned, so the 12480-vs-12544 pitch mismatch that
  change-48 hit on a 3120-wide panel (WTLIntelGfx#14) should **not** happen here.
- Linux scanned out a Tile4 framebuffer. Under OpenCore/GOP the boot FB is linear. Stage 2 of XeGfx reports where
  that framebuffer sits in the GGTT (`plane-surf-1-a`). XeGfx 0.0.48's stage 4 moves it off `GUC_GGTT_TOP
  0xFEE00000` itself (PR #16), so **XgFbMove.kext is NOT needed**. Don't install it.
- Backlight: Linux `intel_backlight`, max 400, type raw. That means display-engine PWM, not DPCD AUX. This matches
  the ThinkBook's PWM case (brightness/ in samwu07's repo).
- PCI: iGPU at `00:02.0`. Wi-Fi at RP08 `00:1C.7` → bus 3. NVMe and SD card on other root ports.

## 4. The plan (gates, each stopping on failure)

The ThinkBook route works on Sequoia: **OpenCore injects XeGfx** (Kernel/Add) and the kext stays idle until you
load it by hand. The other route, XeGfx in the AuxKC via `/Library/Extensions`, **hard-froze the ThinkBook desktop
about a minute after login even though XeGfx never started**. Don't put XeGfx.kext in `/Library/Extensions`.

### Gate 0: baseline (no risk)
1. `sudo bash scripts/collect-baseline.sh`. It saves `sw_vers`, SIP, third-party kexts, `ioreg` GFX0/framebuffer,
   system_profiler and a filtered boot log to `/Volumes/OPENCORE/XEGFX-HANDOFF/reports/baseline-*`, so the Linux
   side can read them too.
2. Check that the touchpad, audio and keyboard work. Note it in the report. That isn't the goal, but it's the
   baseline.
3. Install the Xcode Command Line Tools (`xcode-select --install`) for `python3`, `clang` and `codesign`.

### Gate 1: XeGfx stages 1-2 (read-only)
1. `sudo bash scripts/efi-switch.sh xegfx`, then reboot. Check that the desktop still comes up and wait 10-15 min.
   The ThinkBook froze in the AuxKC route, not the injected one, but watch for it anyway.
2. `sudo bash scripts/run-xegfx-stages.sh 2`. Reports go to `XEGFX-HANDOFF/reports/stages-*`.
3. Read `XeGfxProbe` in the reports: device-id `7d51`, GMD_ID, stolen base, `plane-surf-1-a`, `boot-fb-size`,
   pipe A counters. Write down where the framebuffer sits in the GGTT.

### Gate 2: stages 3-6 (i915 up, GPU work)
1. `sudo bash scripts/run-xegfx-stages.sh 4`. This is i915 init with display code skipped. Afterwards the panel
   must still show the desktop: no black screen and no band. Check `xegfx-fbmove` / "stage 4 boot framebuffer
   move" in the log.
2. `... 6`. Expect work on rcs0/bcs0/ccs0 to come back right. On this machine XeGfx 0.0.48 skips the
   standalone media GT because its FreeBSD port lacks MEI. Stage 6 tests the engines i915 exposes.
3. If a stage panics, the watchdog (`debug.xegfx_wdog=60`) turns a stall into a panic. After the reboot, run
   `scripts/collect-after-crash.sh`. **Don't rerun a stage that failed in the same boot.** Rerunning stage 4
   initialises i915 a second time on top of the first.

### Gate 3: Metal stack (XeGfxAccel, XeGfxIntelFB, XeGfxAGDC, plugin, Mesa ANV, libdrm)
Prebuilt binaries exist for **Sequoia 15.8.1 / 7D55**: samwu07's release `xegfx-drivers-20261104-0140.zip`,
downloaded to `XEGFX-HANDOFF/downloads/`. They are licensed PolyForm Noncommercial, which is fine for personal
use. Most of it should be device-agnostic:
- `XeGfxAccel.kext` 0.9.5 matches any `8086` GPU with `nmxgpu-claimed`, which XeGfx sets in stage 7. No change.
- `XeGfxIntelFB.kext` 0.9.4 only matches `0x7d558086 0x7d678086`. **Add `0x7d518086`** to `IOPCIMatch`, then
  re-sign ad hoc (`codesign -f -s - --deep`). samwu07's `metal-stack/desktop/install-xeintelfb.sh` already does
  exactly this for 7D55: copy it and change `MATCH`.
- `XeGfxAGDC.kext` 0.1.1 matches on IOResources. No change.
- For the private probe, `NVMTLDriver.bundle` with the LLVM 20 AIR reader goes in `/Library/XeGfx/metal/`.
  Mesa ANV's `libvulkan_intel.dylib`, `libdrm.2.dylib`, `libnvmtl_translate.dylib`, and `intel_icd.json` go in
  `/Library/GPUBundles/nvmtl/`. In Gate 4 the plugin goes in `/Library/GPUBundles/`. Check that Mesa ANV
  recognises `0x7d51`. It calls this GPU family `arl`, and change-48 saw "Intel(R) Graphics (ARL)" on 7D51.
- For the private probe, run `sudo bash scripts/install-metal-probe.sh` after stage 6, reboot, mount the ESP,
  then run `sudo bash scripts/run-xegfx-stages.sh 7`. Confirm `NMXAccel` attaches and run
  `bash scripts/test-metal-probe.sh` as the logged-in user. Both Metal compute and draw must pass. Check `LOG.md`
  before repeating any install or reboot step.
- After the private CoreDisplay probe builds `GPUPass`, `ColorFill`, and `TextureCopy`, run
  `sudo bash scripts/install-xegfx-framebuffer.sh`. It adds `7D51` to XeGfxIntelFB, signs the kext, and backs
  up the auxiliary collection. Reboot and check that `XeGfxIntelFramebuffer` owns the built-in panel.
- After the Intel framebuffer boots, use `sudo bash scripts/install-xegfx-desktop-component.sh compositor REPORT`
  with the private CoreDisplay probe report directory. It installs XeGfxAGDC and the verified plugin with an
  armed-only WindowServer allow-list. Reboot, run stages 1–7, and save your work before activation.
- Installing kexts into the AuxKC needs SIP to allow untrusted kexts. 0x0803 already includes
  `CSR_ALLOW_UNTRUSTED_KEXTS`. The ThinkBook used **`csr-active-config = 430A0000` (0xA43)** and the boot-args
  `amfi_get_out_of_my_way=0x1 amfi=0x80 ipc_control_port_options=0` so WindowServer can load the unsigned plugin.
  Change one thing per reboot.
- Back up `/Library/KernelCollections/AuxiliaryKernelExtensions.kc` before the first AuxKC change.

### Gate 4: desktop on the GPU
- Run `sudo bash scripts/desktop-on.sh --restart-windowserver` after stage 7. It checks the Intel framebuffer and
  sets the AGDC and accelerator switches, then restarts WindowServer. Log in again and check the report's
  display-pipe counters. A guard disables the plugin for WindowServer if it keeps restarting.
- Then turn on zero-copy flip (samwu07 `desktop/xeflip.sh try`; on 7D55: 602 flipped, 0 copied).
- Then autostart (`desktop/autostart.sh on`). It has a guard: a run that isn't confirmed blocks the next one.
- Brightness: `brightness/` in samwu07's repo (SSDT-PNLF is already in the EFI, and XeGfxIntelFB 0.9.7's
  XeGfxBacklight writes the PWM).

## 5. Pitfalls already found by others (read before debugging)

- `xegfx.nvram_trace=0` is required (it's the default in 0.0.48, but it's also set in boot-args). NVRAM writes run
  in SMM on this class of firmware and caused the I-116 whole-CPU stall.
- If the framebuffer crosses `0xFEE00000`, the GuC image is drawn over the panel as a "band". 0.0.48 handles the
  move. If stage 4 reports the move was refused, stop.
- The `AGDC_FB_CLASS` must equal the framebuffer's real class name, or AGDC silently mismatches and IOP never finds
  a display pipe (change-48).
- `performTransaction()` returns 0xe00002c7 silently until `gNvIop` is set: `debug.xegfxaccel_iop=1` (change-48's
  build) or `debug.nvaccel_iop=1` (samwu07's). Names differ between builds, so check `sysctl -a | grep -i accel`.
- `debug.xegfxaccelfb` must be written as **3**. Reading it back shows 1, and that's normal.
- A WindowServer crash loop on the Intel Metal device means CoreDisplay's `default.metallib` needs the AIR bitcode
  reader (LLVM 20 `libLLVM.dylib` in the plugin's `air-runtime/`). samwu07's `desktop/add-bitcode-reader.sh` adds it.
- "0 frames reached the accelerator": the GOP framebuffer lives in stolen memory outside the GFX0 BARs, so
  IONDRVFramebuffer never came online. XeGfxIntelFB's `bootvram.patch` fixes this by adding the console range as
  device memory.
- XeGfxIntelFB boot guard: two starts without WindowServer means it declines from then on. Reset it with
  `sudo nvram xeintelfb-starts=%00` (and `nmintelfb-starts=%00`), then reboot.
- Under XeGfx, the panel stays at the firmware mode (no mode-set).
- `kmutil showloaded ... | grep -q` + `pipefail` = SIGPIPE false negatives. Use `grep > /dev/null`.
- Write a stage's logs and `sync` **before** the next stage. A hang loses anything that wasn't synced.

## 8. Rollback and rescue

- **The EFI config won't boot:** F12 → internal NVMe → Arch, then
  `sudo mount /dev/sda1 /mnt && sudo cp /mnt/XEGFX-HANDOFF/efi/config-safe.plist /mnt/EFI/OC/config.plist`.
  Or from macOS Recovery Terminal: `diskutil mount disk<N>s1` and the same `cp`.
- **A kext in the AuxKC breaks the boot:** boot with `-x` (Safe Mode doesn't load the AuxKC), remove the kext from
  `/Library/Extensions`, `sudo kmutil install --update-all`, reboot. Or in Recovery Terminal, restore the backed-up
  `AuxiliaryKernelExtensions.kc`.
- **WindowServer loops on the Intel device:** boot-arg `-xegfxnoauto` (samwu07 autostart), or
  `/Library/XeGfx/desktop/autostart-off`.
- Keep one known-good path at all times: `config-safe.plist` + nothing installed in `/Library/Extensions` boots
  to the UEFIGraphicsFB desktop.
